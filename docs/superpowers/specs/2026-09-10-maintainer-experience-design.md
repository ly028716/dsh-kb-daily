# 维护者体验文档设计

## 目标

为 `@ly028716/dsh-kb-daily` 提供可直接使用的贡献、问题报告、安全报告、架构、故障排查和版本迁移入口，降低新维护者定位问题和提交变更的成本。

## 范围

本次只补充文档与 GitHub 模板，不修改运行时行为。文档必须以仓库当前已实现能力为准，不把尚未落地的报告结构、历史补报、上下文预算或增值分析能力写成已支持功能。

## 文档组成

- `CONTRIBUTING.md`：开发环境、测试命令、代码规范、提交和 PR 检查清单。
- `.github/ISSUE_TEMPLATE/bug_report.md`：结构化 Bug 报告，要求脱敏日志和最小复现。
- `.github/ISSUE_TEMPLATE/feature_request.md`：结构化功能建议，要求说明问题、范围和验收标准。
- `.github/ISSUE_TEMPLATE/security_vulnerability.md`：安全问题私下报告引导，不要求公开漏洞细节。
- `SECURITY.md`：支持版本、安全边界、报告流程和敏感信息处理。
- `docs/architecture.md`：Mermaid 架构图和关键数据流，覆盖插件、工具、审批、runner、文件系统、Git diff 与诊断。
- `docs/troubleshooting.md`：安装加载、权限路径、审批、日报生成、Git、生命周期和诊断问题。
- `docs/migration-0.1.0-rc.8-to-0.2.0.md`：兼容性、配置检查、报告/安全行为、验证和回滚说明。

## 迁移说明原则

迁移文档只描述当前仓库可以验证的行为：`0.1.0-rc.8` 的配置字段保持兼容，报告写入仍然独占创建，默认写入审批为 `ask`，路径安全和运行诊断行为需要在升级后复核。未来功能单独列为“尚未包含在本次迁移中的计划”，不伪装成现有 API。

## 验收标准

- README 中有维护者文档入口。
- GitHub 模板能直接创建 Bug、功能和安全问题草稿。
- 架构图使用 Mermaid，渲染失败时正文仍可独立阅读。
- 排障手册的每个症状都有检查命令、可能原因和安全处理建议。
- 迁移说明包含升级前备份、配置核对、验证命令和回滚路径。
- 文档通过链接、Markdown 结构和敏感信息检查。
